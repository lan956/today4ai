# Today for AI → RSS

Unofficial RSS 2.0 feeds for <https://todayforai.com>, generated by a scheduled
GitHub Action from the site's own public agent API. No API key, no scraped
layout, no third-party services.

| Feed | What |
| --- | --- |
| `feed.xml` | Latest curated AI intelligence, rolling 24h window (up to 30 items) |
| `hot.xml` | Trending story radar, top 10 by cross-source heat, links to site story pages |

After the first workflow run your URLs are:

```
https://raw.githubusercontent.com/<you>/<repo>/main/feed.xml
https://raw.githubusercontent.com/<you>/<repo>/main/hot.xml
```

(or `https://<you>.github.io/<repo>/feed.xml` if you switch to Pages — see below)

## Setup

1. Create a repo and push this folder (keep the paths: `tfa_rss.py` and
   `.github/workflows/feed.yml`).
2. Repo → **Settings → Actions → General → Workflow permissions** →
   **Read and write**. The job commits the refreshed XML back to `main`.
3. **Actions** tab → `feed` → **Run workflow**. It commits `feed.xml`,
   `hot.xml`, `index.html` and then keeps refreshing every 3 hours.
4. Subscribe to the raw URL above in your reader.

No Pages configuration is required. If you prefer the nicer
`https://<you>.github.io/<repo>/` URL instead of `raw.githubusercontent.com`:

1. Settings → **Pages** → Source: **Deploy from a branch** → `main` / `/ (root)`.
2. Add a repo **variable** `FEED_BASE_URL` = `https://<you>.github.io/<repo>`
   (Settings → Secrets and variables → Actions → Variables) so
   `<atom:link rel="self">` points at the right place.
3. Subscribe to `https://<you>.github.io/<repo>/feed.xml`.

## Why not the site's own feed

I read <https://todayforai.com/en/agent>, `/api/v1/agent` and `/llms.txt`:

| Endpoint | Reality |
| --- | --- |
| `/api/v1/feed` | Documented as "RSS / Atom 订阅源" — it returns `application/json`. Every item sampled across 3 pages was `channel: explore` (glossary terms like TPU), not news. |
| `/rss.xml`, `/feed.xml`, `/atom.xml` | Return the site's 404 page (HTML). |
| `/api/v1/agent/latest` | **Real source.** `window` (24h/7d), `mode` (selected/all), `category` (llm/agent/opensource/tools/compute), `limit` 1–30. Chinese title/summary, tags, editorial "why it matters", source name, original URL, score. |
| `/api/v1/agent/hot` | Trending stories, `limit` 1–20, each with a site story page. |
| `/api/v1/agent/daily`, `/search`, `/stories/{id}` | Daily briefing, search, timelines. |
| `/api/mcp` | Remote MCP server exposing the same five tools. |

Rate limit is 60 requests/min per IP (`429` + `Retry-After`; the script backs
off). Each run makes **2 requests**: the API call and one fetch of `/en/news`.

## How it works

1. `python tfa_rss.py gen` pulls `/api/v1/agent/latest` and `/api/v1/agent/hot`.
2. The JSON API is Chinese-only, so English `title_en` / `summary_en` are merged
   in from the `/en/news` page payload by article id. If that page changes, the
   feed silently falls back to the Chinese text instead of breaking.
3. Valid XML is written to `feed.xml`, `hot.xml`, `index.html`; the workflow
   commits only when something changed.

Item `<link>` and `<guid>` point at the **original source** article. The site has
no per-article page reachable by id (`/en/news/<id>` is 404) and its news list
emits no `href`s (details open client-side), so there is nothing site-native to
link to — except hot-radar stories, which do link to `todayforai.com/en/story/…`.

## Tuning

Edit the command in `.github/workflows/feed.yml`:

```bash
python tfa_rss.py gen --out . --base-url "$base" \
  --window 7d --mode selected --category agent --limit 20
```

| Flag | Values | Default |
| --- | --- | --- |
| `--window` | `24h`, `7d` | `24h` |
| `--mode` | `all`, `selected` (editor-picked only) | `all` |
| `--category` | `llm`, `agent`, `opensource`, `tools`, `compute` | all |
| `--limit` | 1–30 | 30 |
| `--hot-limit` | 1–20 | 10 |
| `--no-en` | skip English merge (fewer requests) | off |

Change the schedule with the `cron:` line (`"17 */3 * * *"`). GitHub's scheduler
is best-effort and can lag by a few minutes under load.

## Local use

```bash
python tfa_rss.py gen --out .          # snapshot into the current folder
python tfa_rss.py serve --port 8787    # http://127.0.0.1:8787/feed.xml + /hot.xml
```

`serve` refreshes lazily (default 10 min) and keeps serving the last good copy
if upstream fails. Python 3.11+ and the standard library only — nothing to pip
install, so the Action needs no cache step.

## Optional: TinyFish fallback

Not needed under normal conditions. If GitHub's runner IPs ever get blocked by
the site (403/429), the script retries each failed request through the
[TinyFish Fetch API](https://docs.tinyfish.ai/fetch-api) — but only if a key is
present:

1. Get a key at <https://agent.tinyfish.ai/api-keys>.
2. Repo → Settings → Secrets and variables → Actions → **Secrets** →
   `TINYFISH_API_KEY`.

Without the secret the script simply fails loudly, and the workflow keeps the
previous feed in place.

### Secret hygiene

The key is treated as radioactive:

- **Env only.** Read from `TINYFISH_API_KEY` at call time. Never in argv, never
  in a file, never in a URL/query string — it goes in the `X-API-Key` header, so
  it cannot end up in proxy or server access logs.
- **Step-scoped in CI.** Declared on the `Build feeds` step only, so the
  `Commit changed feeds` step never even has it in its environment.
- **No redirects.** Requests use a redirect handler that raises instead of
  following, so the header can't be replayed to another host.
- **Errors stay dumb.** Failures report `http <code> for <url>` — no request
  headers, no body, and exception chaining is suppressed (`from None`).
- **Scrubbed before write.** Every output goes through `redact()`, and
  `write_out()` aborts with a non-zero exit if the key appears anywhere in
  `feed.xml`, `hot.xml` or `index.html`. Nothing the workflow commits can carry
  it.
- **Nothing to leak in history.** The repo contains no key, no `.env`; the
  `.gitignore` covers `.env*`. Rotate the secret in GitHub if it ever leaks —
  the code needs no change.
- GitHub Actions masks secret values in logs automatically; the redaction above
  is the belt to that suspenders, since masks don't protect committed files.

## Notes & limits

- The feed is a rolling window, not an archive: once an item leaves the API's
  24h (or 7d) window it disappears. There is no state file by design — a reader
  polling every few hours never misses anything.
- `pubDate` keeps the source's `+08:00` offset.
- Titles/summaries are English when the merge hits, Chinese otherwise. Tags are
  always the site's (Chinese) tags.
- Unofficial and unaffiliated; content belongs to todayforai.com and the linked
  publishers. Respect their rate limit and don't lower the schedule below a few
  minutes.
